# Agent Instructions: `screen-manager` Service & UI Architecture

This document defines the behavioral, architectural, and engineering rules for AI agents developing, refactoring, and testing the `screen-manager` service and its UI / display components.

---

## 1. Target Platform & Compilation Environment

* **Target Hardware:** **Raspberry Pi 3 Model B** (Broadcom BCM2837, quad-core ARM Cortex-A53 `aarch64`, running DietPi / Debian 13 Trixie).
* **Primary Rust Target:** `aarch64-unknown-linux-gnu` with Cortex-A53 pipeline scheduling (`-C target-cpu=cortex-a53`) and hardware ARM NEON SIMD vectorization with crypto disabled (`-C target-feature=+neon,-aes,-sha2`), configured in [`.cargo/config.toml`](../../.cargo/config.toml).
* **Workspace Build Profiles & Fast Host Linker:**
  * **Raspberry Pi Release Deployment (`[profile.release]`):** Tuned for maximal runtime performance on Cortex-A53 (`opt-level = 3`, `lto = "fat"`, `codegen-units = 1`, `panic = "abort"`, `strip = true`).
  * **Development & Test Profile (`[profile.dev]`):** Configured with `debug = 1` (line tables only) to accelerate test and coverage compilations while preserving full backtraces.
  * **Host Linker (`x86_64-unknown-linux-gnu`):** Uses `-C link-arg=-fuse-ld=lld` in [`.cargo/config.toml`](../../.cargo/config.toml).
* **Building for the Target Platform:**
  Always compile binaries for the Raspberry Pi 3 `aarch64-unknown-linux-gnu` target:
  ```bash
  cargo build -p screen-manager --target aarch64-unknown-linux-gnu --release --bins
  ```
* **Live Hardware Testing via SSH (`root@192.168.2.120`):**
  * You can test compiled `aarch64` binaries directly on the live Raspberry Pi 3 over SSH at `root@192.168.2.120`.
  * **Strict Non-Destructive Rule:** **Do NOT modify any persistent files, configurations, or running services on the SSH server.** Copy test/utility binaries only to `/tmp/<binary>`, execute them, and remove `/tmp/<binary>` immediately afterward. **Exception:** when the user explicitly asks to deploy/install release binaries, copy them to `/usr/local/bin` (never touch configs or services, and do not restart services unless asked).
  * **Mandatory Deployment Script:** When asked to deploy/install release binaries to the SSH server, ALWAYS use the provided helper script [`scripts/deploy_binaries.sh`](../../scripts/deploy_binaries.sh) instead of manually running `scp`/`ssh` commands. It handles copying binaries from the release build output to `/usr/local/bin`, performs sha256 integrity verification on both ends, and sets executable permissions. Usage: `scripts/deploy_binaries.sh screen-manager` or `scripts/deploy_binaries.sh`.

## 2. Primary Engineering Rule: Microsoft Pragmatic Rust Guidelines

All Rust code in this repository **MUST** strictly adhere to the **Microsoft Pragmatic Rust Guidelines** already downloaded in this repository:
* **Local Reference:** [`services/.guidelines/microsoft-rust-guidelines.md`](../.guidelines/microsoft-rust-guidelines.md)

Before designing types, writing modules, implementing error handling, or writing tests, consult [`microsoft-rust-guidelines.md`](../.guidelines/microsoft-rust-guidelines.md) and ensure all newly created or modified code complies with its rules.

### Key Guidelines Checklist
0. **Mandatory Ecosystem Reuse over Reinvention (Kernel & Crates First):**
   * Never implement raw register/byte-level hardware protocols from scratch without evaluating existing solutions:
     1. **Linux Kernel Subsystems First:** Check if Linux has a kernel driver (e.g., Industrial I/O `IIO` for ambient light/IMUs, `hwmon` for thermals, ALSA for audio DACs, `w1-gpio`/`w1_therm` for 1-Wire). Consuming sysfs/devfs is preferred over bit-banging raw bus transactions in user space.
     2. **Crates.io & `embedded-hal` Drivers Second:** If user-space I2C/SPI is required (via `rppal`), search `crates.io` for existing drivers.
   * **Crates.io Search Is Mandatory (Pre-Implementation Gate):** Before writing ANY driver, state machine, protocol parser, decoder, or debouncer, run concrete `cargo search` queries covering the functionality (e.g., "quadrature", "debounce", "rgb led") and read the vendored source of top candidates in `~/.cargo/registry/src/`. Hand-rolling logic a published crate already implements is a process violation even if trivially correct; document rejection reasons (license, maintenance, hardware mismatch) before hand-rolling any remainder.
   * **Interactive User Decision Mandate:**
     - When multiple options exist, research each (maintenance, license, dependencies, `embedded-hal` compatibility, async support) and present a structured trade-off comparison to the user to choose.
     - When a single option exists, explicitly inform and prompt the user before adding a new crate to `Cargo.toml`.
   * **Domain Wrapping & Mocking:** Wrap the external driver or kernel interface inside `Backend::Hardware` behind the project's domain models (`new_mocked()`, canonical errors, strong newtypes) so host-testability and CI coverage are preserved.
1. **Mockable I/O & Hardware (`M-MOCKABLE-SYSCALLS`, `M-DI-HIERARCHY`):**
   * Hardware drivers and external I/O types must never perform unmockable ad-hoc syscalls or offer `Default` implementations (`#[expect(clippy::new_without_default, reason = "...")]`).
   * Provide inherent mocking via `new_mocked() -> (Self, MockCtrl)` using an internal backend enum (`Sysfs`/`Hardware` vs. `Mock`) so tests can inject readings and faults deterministically without physical hardware.
   * *Project Convention (`M-TEST-UTIL`):* Diagnostic and peripheral drivers intentionally provide inherent `new_mocked()` companion controllers unconditionally in production builds (and `speaker_common::diag::ScopedTempDir` is similarly exported unconditionally) to guarantee that CI coverage verification, binary unit tests, integration tests, and standalone diagnostic utilities execute host-agnostically without physical hardware or separate test-only feature flags.
   * **Integration Test Discipline (Tests Belong Under `tests/`, Never in `src/`):** All test logic must reside exclusively under `tests/` (`tests/*_integration.rs`, `tests/cli_tests.rs`). Never write `#[cfg(test)] mod tests { ... }` or unit test functions within `src/`. Expose mock companion controllers via `test-util` or inherent `new_mocked()` methods to keep `src/` strictly production code.
2. **Three-Fold Purpose for Hardware Classes:**
   Every hardware peripheral abstraction in `speaker_hardware` must serve three purposes:
   * **Core Service:** Cheaply cloneable (`Arc`-backed per `M-SERVICES-CLONE`), `Send + Sync` (`M-TYPES-SEND`), with non-blocking `async` methods that isolate slow/blocking hardware I/O on `tokio::task::spawn_blocking`.
   * **Tests & Mocking:** Controllable via its companion mock handle (`new_mocked()`) and/or custom sysfs paths for unit and integration testing (`tests/`).
   * **Diagnostic CLI Utilities (`tools/diagnostics/src/bin/*.rs`):** Usable directly in standalone Rust utilities that print hardware GPIO pinout metadata (`GpioPinInfo`: BCM pin, physical header pin, bus protocol, DT overlay) alongside live telemetry.
3. **Strong Typing & Invariant Guards (`M-STRONG-TYPES`, `M-STRONG-TYPES-GUARD`, `C-NEWTYPE`):**
   * Avoid primitive obsession. Use domain newtypes (`BcmPin`, `PhysicalPin`, `Temperature`, `SensorId`, `VolumePercent`, `AttenuationDb`) that guard their invariants at construction time via fallible constructors (`from_*`, `parse`, `TryFrom`, `FromStr`).
   * Use `Path` / `PathBuf` for filesystem paths (`M-STRONG-TYPES`) and `Box<str>` / `Box<[T]>` for immutable owned sequences (`M-BOX-DST`).
4. **Canonical Error Structs (`M-ERRORS-CANONICAL-STRUCTS`, `M-FROM-ERROR`, `M-PANIC-IS-STOP`):**
   * Subsystem errors must be canonical structs (e.g., `TempError`, `PinError`) wrapping a non-public `ErrorKind` and a captured `std::backtrace::Backtrace`, exposing `is_*()` query predicates and implementing `Debug`, `Display`, and `std::error::Error`.
   * Never use `.unwrap()` or `.expect()` on fallible runtime I/O paths.
5. **Single Item Path & Clean Exports (`M-SINGLE-ITEM-PATH`, `M-NO-GLOB-REEXPORTS`, `M-DOC-INLINE`):**
   * Each public item must be reachable through a single canonical path. Use `pub(crate) mod ...` with explicit `#[doc(inline)] pub use ...` re-exports rather than wildcard globs.
6. **Documentation, Lints & Static Verification (`M-MODULE-DOCS`, `M-CANONICAL-DOCS`, `M-FIRST-DOC-SENTENCE`, `M-LINT-OVERRIDE-EXPECT`, `M-STATIC-VERIFICATION`):**
   * Every module must begin with `//!` documentation; every public item must have `///` documentation whose first sentence is a single line of ~15 words or fewer, followed by `# Examples`, `# Errors`, and `# Panics` sections where applicable. Do not write `# Parameters` tables or meta design journals (`M-NO-META-DESIGN-DOCUMENTATION`).
   * Use `#[expect(..., reason = "...")]` instead of `#[allow(...)]` for lint overrides.
   * All code must format cleanly with `cargo fmt --check` and pass `cargo clippy --all-targets -- -D warnings` with zero warnings.
7. **Mandatory Code Coverage Verification (`M-INTEGRATION-TESTS`, `M-TEST-UTIL` & Repository Coverage Mandate):**
   * **Always check code coverage:** Run `cargo llvm-cov --manifest-path services/screen-manager/Cargo.toml --target x86_64-unknown-linux-gnu` before completing tasks or submitting changes.
   * **Target Standards:** Maintain **>85%–90%+** line and function coverage across the library, hardware modules, and diagnostic CLI binaries.
   * **Testable CLI Utilities:** Architect CLI diagnostic binaries with modular, testable entrypoints (`fn run_app(sensor: &Sensor, opts: &CliOptions) -> ExitCode`) to enable deterministic unit and integration testing of CLI flags, JSON outputs, session summaries, and error handling without physical hardware.
   * **Thorough Mock & Invariant Coverage:** Test domain invariant bounds, conversions, all mock state controls, and fault injections. Isolated physical hardware syscalls (e.g., `/dev/i2c-1`) must have their surrounding logic completely tested.
8. **Code Simplification & Deduplication (`screen-manager` Architecture):**
   * **Shared Diagnostic & Runtime Infrastructure (`speaker_common::diag`, `speaker_common::runtime`):** Do not copy-paste CLI scaffolding (`CommonCliOptions::parse_common_flag`, `parse_args_with_common`, `OutputFormat`, `NumericStats`, `resolve_cli_opts`, `format_timestamp`, `next_arg_value`, `parse_count_arg`, `parse_interval_arg`, `fahrenheit`, `foot_candles`, `round_2dp`, `ScopedTempDir`) across `tools/diagnostics/src/bin/read_*.rs` utilities or `tests/*.rs`. Use `speaker_common::diag` for shared CLI/test helpers (keeping `diag` independent of `hardware` so the dependency edge is strictly `hardware -> diag`) and `speaker_common::runtime::run_blocking` / `abort_and_map` for `spawn_blocking` task execution and cancellation testing. Shared utilities like `ScopedTempDir` must offer a fallible constructor (`try_new`) alongside infallible test conveniences. Diagnostic loop termination must break consistently on cumulative sample stats (`stats.total_reads() >= limit` / `stats.samples.total_reads() >= limit`) to ensure summary metrics and exit codes stay synchronized.
   * **Make Invalid States Unrepresentable & Avoid Derived Fields:** Use sum types (`I2cDetail::Message | I2cDetail::Source`, `SimSource::Lux | SimSource::Raw`) instead of parallel `Option` fields in error kinds and mock state structs. Eliminate speculative/dead error variants (e.g. `Io` variants when the driver already produces wrapped I2C errors). Do not store derived fields (such as `foot_candles` on `LightDiagnostics`) or duplicate `min`/`max` tracking alongside `NumericStats`. Use strongly-typed newtypes (`PhysicalPin::new(1)`, `PhysicalPin::new(9)`) rather than raw string slices for hardware metadata pin descriptors.
   * **Enforce Parsing & Backtrace-Free Machine Summaries at the Domain Boundary (`M-STRONG-TYPES-GUARD`):** Implement both programmatic constructors (`SensorId::parse`, `I2cAddress::new`, `TryFrom`) and soft user-facing string parsers (`SensorId::parse_str`, `I2cAddress::parse_hex` returning `Result<Self, String>`) sharing a zero-allocation validator on the domain type in `hardware::*`, rejecting signed inputs (`+`, `-`) both before and after any `0x`/`0X` prefix. Expose a single-line `err.summary()` method on canonical errors (`LightError`, `TempError`) via `impl_canonical_error_display!` for `NDJSON` telemetry so `RUST_BACKTRACE=1` never injects multi-line stack traces into machine streams.
   * **Minimal Surface Area & Host-Testable State Machines (`HwState`):** Encapsulate driver state transitions and settle-time calculations on `HwState` (`prepare_read`, `record_power_down`, `record_wake_or_reset`, `record_mode_change`) so they are unit-testable on any host. Prefer `#[derive(Copy)]` on small value-type option structs, bare `?` error propagation via `From`, `Duration::checked_sub` for settle calculations, and struct-update syntax (`..CliOptions::default()`) in tests.
   * **Upfront Datasheet & Concurrency Checklist for `hardware::*`:**
     1. Use datasheet **maximum** conversion times (180 ms), never typical times, when calculating settle delays.
     2. Standardize on Continuous High-Resolution Mode for ambient lighting and display brightness; avoid speculative one-shot or alternate-resolution modes that introduce state-machine races and settle complexity.
     3. Track reset/transition times (`last_transition: Instant`) and explicit sleep state (`powered: bool`) inside `HwState` so callers never have to guess settle times and reads while powered down return a typed `is_powered_down()` error.
     4. Serialize all bus transactions (`power_down`, `reset`, `read_lux`) inside a single `Mutex<HardwareDevice>` wrapping the `embedded-hal` driver; do not nest redundant per-bus mutexes.
     5. Assert that bus numbers passed to platform-specific pinout constructors (`I2cHardwareInfo::rpi3_with_bus_and_address`) match the physical hardware controller modeled.
     6. Re-arm continuous mode conversions on reset per datasheet so readings do not stall.
     7. Mutate internal driver state (`HwState: powered, last_transition`) strictly **after** all fallible bus transactions succeed.
    * **KMS Display Backend (`backend-linuxkms` + FemtoVG) & Offscreen Test Harness (`crate::ui::runtime`, `crate::ui::framebuffer`):**
      1. Production rendering goes through Slint's `backend-linuxkms` (noseat) with the FemtoVG renderer — the custom fbdev `/dev/fb0` scanout path is gone. The process must own exactly ONE Slint window and run exactly ONE `slint::run_event_loop()` for its entire lifetime: splash and boot-check phases are in-window overlays (`boot_splash_visible` on `MainWindow`), never a second window or a re-entered event loop. Per-tick application logic (encoder polling via `slint::Timer`, Bluetooth sync, marquee clock) belongs in `Timer` callbacks — never a manual render loop that calls `request_redraw()` itself.
      2. Keep `renderer-software` + `software-renderer-systemfonts` enabled only for the offscreen test harness; the workspace must never re-add `compat-1-2` (it forces libseat, which is broken against this appliance's logind) while `backend-linuxkms` is enabled — use `backend-linuxkms-noseat` (direct `/dev/dri/*`, libinput via udev seat0).
      3. `Framebuffer` is a TEST-ONLY offscreen harness: `Framebuffer::new_mocked() -> (Framebuffer, FramebufferMockCtrl)`, compile-time 800x480 32bpp BGRX geometry proven via `const _` invariant blocks (never dynamic width/height parameters), `Bgrx8888Pixel` implementing Slint's `TargetPixel` for capture rendering. Production must never open `/dev/fb0` or write scanout code.
      4. Enforce the glibc 2.17 math-symbol baseline for aarch64 cross-builds via `speaker_common::glibc_compat!()` (invoked from `main.rs`; wraps the `global_asm!` `.symver acosf/atan2f` directives), never by hand in per-crate modules.
      5. Retain underlying foreign errors (`io::Error`) as typed error fields (`source: io::Error` in `FramebufferErrorKind::Io`) and implement `std::error::Error::source(&self)` per `M-ERRORS-STD-SOURCE`.
      6. Never re-export foreign dependency traits (such as `pub use slint::ComponentHandle;`) per `M-FOREIGN-REEXPORTS`.
      7. Guard KMS display acquisition in subprocess tests with `SPEAKER_CORE_HEADLESS=1` (exact value, so `=0` keeps the display enabled) plus the missing-`/dev/dri/card0` early return, so developer hosts and CI never attempt to become DRM master.
      8. Guard Slint float layout properties against `NaN` using explicit boundary checks (`val >= 0.0 ? ... : 0`) to prevent widget layout collapse.
     9. **Dynamic Math Expressions over Hardcoded Pixel Offsets (`M-SLINT-MATH-LAYOUT`):** In Slint UI markup, component layouts, and geometry calculations, always use dynamic mathematical expressions (`(parent.height - self.height) / 2`, `(parent.width - self.width) / 2`, layout centering containers `VerticalLayout { alignment: center; ... }`, or relative percentage/stretch properties) to compute positions, alignments, and sizes. Never manually pre-calculate pixel offsets and hardcode literal numbers into `.slint` files (e.g. `y: 6px`, `y: -5px`, `y: 24px`, or manual top-alignment offsets). Hardcoded literal numbers break whenever parent bounds, padding, themes, or font scales change, introducing subtle visual regressions. Let Slint compute the geometry dynamically.
    10. **Never Read `animation-tick()` in Per-Frame Polling Properties (`M-NO-PERPETUAL-ANIMATION-DRIVER`):** Reading Slint's `animation-tick()` calls `set_has_active_animations()`, permanently marking the animation driver active. Any binding evaluated every frame that touches it pins `has_active_animations() == true` forever, defeating the render loop's power-saving idle branch and pinning ~60% CPU even when the UI is visually static. Drive continuous animations (marquee scrolling) from a self-managed integer frame counter advanced by a Slint `Timer` whose `running` property reflects actual animation need (e.g. `running: root.is_overflow`), with integer-px offsets derived from frame counts.
    11. **Slint Codegen Requires Window-Rooted Exports:** `slint-build` only generates Rust structs for exported components that inherit `Window`; re-exporting a `Rectangle`-rooted component is silently pruned (only a `cargo:warning`). Offscreen helper components must be declared `export component X inherits Window { background: transparent; ... }`.
    12. **Slint Build Script Rerun Is Unreliable — Purge Build Dirs After `.slint` Edits:** `slint-build` emits absolute `rerun-if-changed` paths; when edits do not trigger regeneration (stale fingerprints), the generated code silently lags the `.slint` sources and produces confusing "cannot find component" errors. `rm -rf target/<triple>/{debug,release}/build/screen-manager-* target/<triple>/{debug,release}/.fingerprint/screen-manager-*` after editing `.slint` files, then rebuild.
    13. **Live-Text Marquee Under KMS/FemtoVG — No Secondary Slint Windows (`M-NO-SECONDARY-KMS-WINDOWS`):** The marquee scrolls `MarqueeText` driven by the shared integer `MarqueeCompose.clock` (one 16.65 ms `Timer` in `NowPlayingView`, `step_frames` for 30/60 fps). The old secondary-component strip rasterizer (`MarqueeStripRasterizer` instantiating a second Slint component) was deleted because under `backend-linuxkms` ANY secondary Slint component eagerly creates a real DRM/GL window whose teardown crashed Mesa (`driUnbindContext` SEGV). Instead, `ui/marquee.rs` rasterizes overflowing titles in-process via `swash` into a premultiplied `SharedPixelBuffer<Rgba8Pixel>` (`Image::from_rgba8_premultiplied`, capped at `2048 px` for VideoCore IV `GL_MAX_TEXTURE_SIZE`) on track/scale/theme changes only — zero secondary Slint windows, zero Mesa teardown risk, and no per-frame text shaping.
    14. **FemtoVG Must Be Verified Active — No Silent Renderer Fallback:** The boot log must contain `Using FemtoVG OpenGL renderer` (printed once per window — a second pair means a stray secondary window was created, see item 13/20). `renderer-software` exists only for the offscreen test harness; a GL init failure that silently degrades the appliance to software rendering on the BCM2837 defeats the migration, so renderer identity is part of every live-Pi verification (plan §8). Dead fbdev concepts (`FBIO_WAITFORVSYNC`, shadow-buffer scanline blits, `ScanoutSync`, `run_render_loop*`) must never reappear — presentation is scheduled by Slint's KMS event loop.
    15. **Do Not Force `request_redraw()` per Loop Iteration:** Forcing a redraw request every render-loop iteration defeats `RepaintBufferType::ReusedBuffer` idle detection and burns a full scene traversal per frame. Let Slint timers, real animations, and pushed property values mark the window dirty; the loop's idle branch must sleep on `duration_until_next_timer_update()`.
    16. **Never Toggle `if` Conditionals on Per-Frame Float Conditions (`M-NO-PER-FRAME-ITEM-TREE-CHURN`):** A Slint conditional element (`if cond : Item`) whose condition depends on a per-frame-changing float binding (e.g. `scroll_offset + cycle_distance < width`) flaps when f32 rounding makes the float non-monotonic at the crossing boundary. Every flap destroys and recreates the conditional's item tree, and each destruction invokes `free_graphics_resources` -> `force_screen_refresh`, forcing a full-window redraw (~20-30 ms on BCM2837) on the next frame — measured as a sustained ~70% CPU storm of full 800x480 redraws. Express such conditions in integer frame arithmetic (strictly monotonic, e.g. `(scroll_frame - pause_frames) > cycle_frames - Math.round(width / 1px)`) and keep the element in the item tree permanently, toggling only its `visible` property. Guard with a host-side regression test that drives the real window frame-by-frame and asserts full-window dirty frames stay bounded (`tests/marquee_full_redraw_diagnostic.rs`).
    17. **Animated Micro-Widgets Dirty Their Whole Layout Column (`M-NO-PER-FRAME-ITEM-TREE-CHURN` sibling):** The `AmbientWaveIndicator` bars used `animate height {160ms}` restarted every 180 ms tick; the continuous per-frame geometry transitions dirtied the bar element AND every sibling row below it in the enclosing layout (the 484x28 metadata row plus the 484x86 scrubber row, ~55k px/frame, ~33% CPU on BCM2837) even though the animated elements are a few pixels wide. Layout-level invalidation spreads far beyond the animated widget. Prefer stepped discrete updates from the owning Timer (instant height jumps) over `animate` on per-tick-changing properties in appliance UIs; reserve `animate` for one-shot state transitions (e.g. opacity on play/pause flips).
    18. **Known Slint 1.9.2 Limitation — Text String Changes Dirty the Whole View (~1 Hz budget):** Changing a `Text` element's string (e.g. the mm:ss `position_text` once per second) produces a dirty region spanning the entire enclosing card through Slint 1.9.2's partial-rendering layout cascade — geometry pinning (`width`/`height`), `wrap: no-wrap`, and change-guarded setters do not prevent it. Budget ~2.5% CPU for one such text update per second; do not chase it with speculative workarounds (verified empirically via `tests/marquee_full_redraw_diagnostic.rs` rect sampling).
    19. **Multiple Same-Rate Slint Timers Drift — Use One Shared Clock:** Independent `Timer` elements with identical intervals (e.g. one per marquee instance) drift apart against the vsync cadence, producing alternating dirty events whose combined rate equals the full frame rate and negating any frame-rate halving; each dirty event still renders the union bounding box of all nearby dirty rects. Drive all same-rate animated widgets from a single parent-owned Timer advancing a shared integer clock property; derive per-instance state via `Math.mod(clock, total_frames)` so effective dirty-event rate equals the configured animation fps.
    20. **No Secondary Slint Components in Production (`M-NO-SECONDARY-KMS-WINDOWS` autopsy):** The deleted framebuffer-compose rule (`M-FB-COMPOSE-FINGERPRINT`) died with the Rust composer — there is no row composition left to fingerprint. Its replacement invariant: under `backend-linuxkms`, only the FIRST component may create a window; every later component on the same thread eagerly opens a real DRM/GL surface. Production code must never instantiate a second Slint component (no offscreen rasterizers, no helper windows); the `FramebufferPlatform` test harness may still mint throwaway secondary windows for tests only (`framebuffer_platform_secondary_window_is_independent_of_primary`). Symptom to recognize: a duplicate `Using FemtoVG OpenGL renderer` log pair shortly after boot, then a Mesa teardown SEGV during component drop.
    21. **Top Bar Device Name Must Not Overwrite the Codec Badge (`M-TOPBAR-NAME-GAP`):** The Now Playing top bar lays the device name into the free space between the Bluetooth logo and the right-hand control group. Both edges are read from the live layout (`absolute-position` of the logo image and of the controls group), never from hard-coded pixel offsets, so the name is elided (`overflow: elide`) instead of being painted over the codec badge. Two layout facts make this fragile if ignored: a conditional element (`if cond : Item`) inside a layout **collapses its slot** (the control group re-centers when the codec badge appears or disappears), and the centered name re-centers itself in the gap, so it moves whenever the badge is shown or hidden. Derive geometry from the layout on every evaluation instead of caching it, and guard the invariant with a host-side render test (`tests/top_bar_codec_integration.rs`) that compares rendered pixels instead of hard-coding column offsets.

## 3. Zero-Retry Pre-Push Gate & Continuous Learning

AI agents working on `screen-manager` **MUST** follow the repository-wide **First-Pass PR Quality, Code Simplification & Continuous Learning Protocol** defined canonically in [root `AGENTS.md` (§4)](../../AGENTS.md).

* **Never Block the Render Thread on D-Bus (`M-NO-DBUS-ON-RENDER-THREAD`):** The KMS backend runs exactly one Slint event loop on one thread, so every millisecond spent in a blocking `zbus` call inside a render-thread callback (timer, `on_*` handler, `invoke_from_event_loop`) stalls the whole UI — splash updates, touch input, marquee animation and the preview deadline. Defer *every* blocking system-bus round trip (the BlueZ connect **and** the initial playback/link snapshot reads) to a dedicated worker thread and publish the results through a channel the render thread drains (`BtSharedUpdate` + `apply_shared_bt_state`). "Deferring" a blocking call to a timer that still runs on the render thread is **not** a deferral: the timer callback must not perform D-Bus I/O. The render thread may only apply already-fetched values; anything that needs `Send` data to cross the thread boundary (e.g. the transport command queue) is wired on the render thread behind an `AtomicBool` handshake raised by the worker.
* **Service-Specific Gate Sequence:** Before every push, execute in order:
  1. `cargo fmt -p screen-manager -- --check`
  2. `cargo clippy -p screen-manager --all-targets -- -D warnings`
  3. `cargo llvm-cov -p screen-manager --target x86_64-unknown-linux-gnu --fail-under-lines 90 --fail-under-functions 90`
  4. `cargo build -p screen-manager --target aarch64-unknown-linux-gnu --release --bins`
* **Protocol & Review Rules:** Consult [root `AGENTS.md` (§4.1–§4.3)](../../AGENTS.md) for the 3-Tier review triage classification, mandatory critical analysis of code review comments before fixing (only fix what genuinely makes sense), strict PR blast radius containment, code anti-bloat mandate, and continuous post-review distillation requirements.
